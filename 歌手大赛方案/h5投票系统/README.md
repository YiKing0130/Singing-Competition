# 校园歌手大赛 · H5 投票与大屏系统

零依赖 Node.js 服务 + 三个页面。不需要小程序、不需要审核、不需要数据库服务器。
数据存在 `data/db.json` 一个文件里，拷走就是备份。

---

## 一、30 秒跑起来

```bash
cd h5投票系统
node server.js
```

打开 http://localhost:8080 ，你会看到三个入口：

| 页面 | 地址 | 用途 |
| --- | --- | --- |
| 大屏 | `/screen` | 接投影，全屏播放，实时票数与排名 |
| 投票 | `/vote` | 观众手机扫码进入 |
| 后台 | `/admin` | 流程切换、评委打分、名单与权重 |

默认后台密码 `admin123`，**第一次进去就改掉**（设置区最下面）。

## 二、三种上线方式，按现场情况选

### 方式 A：局域网（最省事，0 元，推荐先试）

电脑和所有手机连同一个 Wi-Fi（或同一个路由器），手机访问 `http://电脑IP:8080`。

启动时控制台会打印局域网地址，比如 `http://192.168.1.23:8080`。

**必须注意两点：**

1. 很多路由器/校园网开了「AP 隔离」，连同一个 Wi-Fi 的设备互相访问不了。**赛前一定要用两部手机实测**。
2. 用手机热点代替路由器也可以，但热点通常只支持 8—10 台设备，超过就有人连不上。

### 方式 B：内网穿透（手机用 4G 也能投，0 元）

适合场地 Wi-Fi 不可靠、或者观众不连同一个网的场景。

```bash
# 以 cpolar 为例（注册后用它们给的 token）
cpolar http 8080
```

会给你一个公网 https 地址，把大屏上的二维码换成这个地址即可。

免费版有带宽限制、每次重启地址会变，**比赛当天早上就启动，地址定了就不要再重启**。

natapp、frp、ngrok 同理。

### 方式 C：云服务器（最稳，约 60—100 元/月）

腾讯云/阿里云最便宜的 2 核 2G 轻量服务器就够。上传整个目录，`node server.js` 跑起来，安全组放行 8080。

想好看一点可以绑域名 + HTTPS，但不是必须——微信里打开 http 也能正常投票。

## 三、二维码怎么来

大屏页会先试着加载 `/qr.png`，没有就自动调用在线接口生成。

**建议赛前自己做一张**（在线接口在现场断网时会失效）：

1. 确定最终访问地址（比如 `http://192.168.1.23:8080/vote`）
2. 用草料二维码 cli.im 生成，下载 PNG
3. 改名 `qr.png`，放进 `public/` 目录

这样即使现场没有外网，二维码也照样显示。

## 五、现场操作：跟着主持人口令点按钮

| 主持人说 | 你点 | 大屏变成 |
| --- | --- | --- |
| 比赛开始，第一位选手 | **比赛进行** → 每唱完一位点 **下一位选手 ▶** | 大大的序号 + 姓名 + 曲目 |
| 全部唱完，请投票 | 填好时长 → **开始倒计时并开放投票** | 票数条实时增长、排名实时洗牌、右侧倒计时 |
| 时间到，投票截止 | **投票截止** | 数字冻结 |
| 下面揭晓评委分 | **揭晓评委分** → 反复点 **揭开下一位** | 逐个亮出评委分 |
| 揭晓观众票 | **揭晓观众票** | 票数从 0 滚到最终值，排名重排 |
| 最终排名 | **最终排名** | 总分排序，前三名高亮 |
| 结束后 | **导出成绩 CSV** | 下载成绩单 |

**投票口令**在右侧栏和底部同时显示，观众投票要输入它——这是防陌生人乱投的一道闸。每场换一次，点「随机换一个」。

## 六、计分规则

评委打 10 分制，观众投的是票，两个数不能直接相加，所以先各自归一化：

```
评委分归一 = 该选手评委平均分 ÷ 全场最高评委平均分 × 100
观众分归一 = 该选手票数     ÷ 全场最高票数      × 100
总分     = 评委分归一 × 评委权重 + 观众分归一 × 观众权重
```

- 用「除以最高分」而不是「除以满分」，是为了让大屏上永远有一条顶到最右边。
- 权重在后台改（默认 60 / 40），改完不用重启，大屏下一轮刷新就生效。
- 同分时按评委分高者优先。

**为什么不用原始分直接加权：** 评委分满分 10，观众票可能几百，量纲差两个数量级，直接加权等于只有票数在起作用。

## 七、防刷票做了什么

1. **设备指纹**：浏览器本地生成唯一 ID + 画布指纹，同一个浏览器只能投一次，服务端也存了一份做二次校验。
2. **口令**：每场一个四字口令，投完即换。
3. **投票窗口**：服务端控制开关和截止时间，窗口关了接口直接拒绝，改前端没用。
4. **记录留痕**：每一票都记了时间、设备指纹和 IP，赛后可以查到异常聚集。

局限也要说清楚：H5 拿不到微信身份，**换设备（清缓存/换浏览器）理论上可以再投一次**。校内比赛用「口令 + 一设备一票」够了；如果这场特别重要，建议叠加「现场发票 + 一人一票」，或者改用小程序（可拿 openid）。

## 八、出问题怎么办

| 现象 | 处理 |
| --- | --- |
| 大屏显示「连接中断」 | 电脑网络断了。切手机热点；页面会自动重连，不用刷新 |
| 手机打不开投票页 | ① 是不是同一个 Wi-Fi ② 路由器开了 AP 隔离 ③ 换 4G + 内网穿透 |
| 有人投不了票，说口令错 | 看大屏右侧口令，注意别把 `0` 和 `O` 搞混；口令不区分大小写 |
| 票数明显异常 | 后台「清空所有投票」重开，同时换口令 |
| 大屏卡住了 | F5 刷新，状态在服务端，刷完就回来了 |
| 电脑挂了 | 换一台电脑跑 `node server.js`，把 `data/db.json` 拷过去，数据不丢 |
| 彻底没网 | 大屏切到「最终排名」放录屏/截图，主持人口播兜底 |

**比赛前一定要做的三件事**：两部手机实测投票、投影实测字号、关掉电脑休眠。

## 九、数据与备份

- 所有数据在 `data/db.json`，每次写入都是先写临时文件再改名，断电不会写坏。
- 赛后把这个文件复制走，就是完整记录（含每一票的时间与设备指纹）。
- 想重置：后台「清空所有投票」只清票；「恢复演示数据」会把选手也重置。

## 十、已知限制（先说清楚，免得到现场才发现）

1. **不能识别同一个人换设备**。H5 方案的固有限制。
2. **投票人数上限**取决于电脑和带宽。单文件 JSON 写入，实测几百人同时投没问题；上千人建议换 SQLite。
3. **统计是"连点"的**：同一个人手速快也可能在 1 秒内点两次——服务端按设备去重，第二次会被拒。
4. **不支持加赛/复活**。流程是"全部唱完 → 统一投票 → 揭晓"，没有复赛。
5. 大屏刷新间隔 2 秒，不是"毫秒级实时"，现场观感上够用。

## 十二、公网穿透（现场必备，已配置好）

校园网普遍开了客户端隔离，手机和电脑在同一个 Wi-Fi 也互相访问不了；而且上百名观众不可能都连校园网。
所以正式使用时走公网隧道：

```bash
./tunnel.sh
```

它做三件事：
1. 用 `localhost.run` 起一条 SSH 隧道（不需要注册、不需要装软件、不需要域名）。
2. 把拿到的公网地址写进 `tunnel.url`。
3. 断了会自动重连。

服务端每次取数都会读 `tunnel.url`，**所以大屏二维码会自动跟着变，不用重启**。

### 现在的地址

以 `tunnel.url` 里的内容为准，格式是 `https://xxxxxxxx.lhr.life`：

- 投票页：`https://xxxxxxxx.lhr.life/vote`
- 大屏：`https://xxxxxxxx.lhr.life/screen`

### 安全设置

- 后台（`/admin` 和所有 `/api/admin/*`）**只允许本机或局域网访问**，公网打开一律 403。
  也就是说后台只能在现场那台电脑上操作，别人拿到公网地址也进不去。
- 后台密码已经改过，不再是 `admin123`。

### 这条隧道的风险，必须知道

1. **免费隧道可能中途断开**。断了 `tunnel.sh` 会自动重连，但**公网地址会变**，之前发的二维码失效。
   大屏会显示新地址的二维码，需要重新投屏提示一次。
2. 免费隧道带宽有限，人多的时候刷新会慢，但投票本身是几十字节的请求，够用。
3. **如果这场比赛很重要（几百人、全程直播），别用免费隧道**——租一台最便宜的云服务器（约 60 元/月），
   把这整个目录拷过去 `node server.js` 就行，地址固定，一次搞定。程序是零依赖的，迁移只要 10 分钟。

### 备用隧道

`localhost.run` 不通时，换 `pinggy`：

```bash
ssh -p 443 -R0:localhost:8080 a.pinggy.io
```

或者 `serveo`：

```bash
ssh -R 80:localhost:8080 serveo.net
```
